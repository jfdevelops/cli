# Contributing

Follow the required conventions linked from AGENTS.md, including the master `jf-git` skill before any Git decision. Read this repository's conventions before its branch, commit, or PR references. Shared convention changes belong in `jfdevelops/skills`. Consumer installs fetch every registered skill from that repository's `main` branch at init/create/sync time; this CLI does not pin skill names or an `@jfdevelops/skills` npm dependency. For this repository's checked-in copies, regenerate snapshots with `pnpm skills:sync` from the sibling checkout and review the resulting diff. `pnpm check:skills` verifies recorded provenance against agent copies and, when `../skills` is present, fails if that checkout drifts. Keep agent-facing instructions independent of a particular agent's tool API.

Run `pnpm check` to typecheck, run the Vitest suite, verify skill copies and recorded provenance, and install the packed executable and check its behavior without a terminal. `pnpm smoke:create` (also run in CI) creates, installs, formats, lints, and builds real projects for each template, formatter, and package manager; it needs network access. Source lives in `src/` with tests beside it as `*.test.ts`; `pnpm build` compiles it to `dist/`. Publishing, commits, and pushes require user authorization.

Bootstrap scripts may regenerate owned files in these empty/new repositories. The future `init` command must instead inspect existing instructions, preview edits, preserve unrelated content, and detect managed-file changes before updating them.

Add a changeset with `pnpm changeset` to every pull request that changes CLI behavior; use `pnpm changeset --empty` for changes without release impact. CI runs the checks on Linux and Windows with Node.js 22 and 24, runs an optional macOS smoke job (5-minute timeout) on pushes to `main`, and requires a changeset on pull requests. Merges to `main` open or update the `chore(release): version packages` pull request; see [.changeset/README.md](.changeset/README.md).
